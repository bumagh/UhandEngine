# UhandEngine 未来一个月更新计划

## 计划目标

在未来一个月内，把 `UhandEngine` 从“SDL2 原型项目”推进到“具备 PhaserJS 对齐方向、并开始面向 AI 协作的 2D 游戏引擎基础框架”。

## 总体原则

- **先稳定架构，再扩展功能**
- **先定义 Scene / Object / Input / Asset 的边界**
- **优先支持 Web 端与 2D 场景心智模型**
- **优先建立 AI 可理解的目录、命名和文档**

## 第 1 周：完成架构收敛

### 本周目标

让当前项目从“原型模块集合”收敛到“清晰的运行时骨架”。

### 重点任务

- 梳理 `main.c` 中的启动、循环、渲染与退出流程
- 明确 `Scene`、`GameObject`、`Component` 的职责边界
- 让 `Scene` 成为真正的运行入口
- 将 `GameObjectList` 的职责并入或挂靠到 `Scene`
- 明确平台层与运行时层分界
- 补齐基础架构文档与模块图

### 交付物

- 稳定的文档目录
- 一版统一命名规范
- Scene-first 架构草案
- 主循环重构清单

### 验收标准

- 新开发者能在 10 分钟内读懂主流程
- 场景系统不再处于“备用模块”状态
- 后续模块扩展都有明确挂载位置

## 第 2 周：建立 Phaser-like 2D 基础能力

### 本周目标

建立 PhaserJS 风格的最小 2D 运行时抽象。

### 重点任务

- 把 `Transform` 升级为 2D first 结构
- 设计 `Sprite`、`Text`、`Container` 的基础抽象
- 补充可见性、层级、父子关系、激活状态
- 建立基础 Display List 或渲染列表
- 抽象输入系统，统一鼠标、键盘和后续触摸行为
- 梳理对象更新顺序与渲染顺序

### 交付物

- 2D 对象模型说明
- 输入系统说明
- 首版对象层级与渲染顺序设计

### 验收标准

- 能清晰创建一个文本对象和一个可点击对象
- 能定义对象位置、显示状态和层级关系
- 基础 API 命名开始统一

## 第 3 周：补齐资源、相机与动画基础

### 本周目标

让引擎具备更接近 PhaserJS 的最小开发体验。

### 重点任务

- 将 `loadMedia()` 升级为 `AssetManager`
- 建立纹理、字体、音频资源的 key 管理
- 设计 Camera 抽象
- 设计 Tween / Animation 最小接口
- 明确 UI 层与世界层分离方式
- 设计简单演示场景

### 交付物

- 资源管理器设计文档
- Camera 与动画系统草案
- 一个最小示例场景说明

### 验收标准

- 资源加载不再依赖零散硬编码
- 相机、动画具备清晰接口边界
- 演示场景可以作为后续 AI 生成模板

## 第 4 周：引入 AI 协作能力与模板化工作流

### 本周目标

让项目具备“对 AI 友好”的最小工作流。

### 重点任务

- 定义 `Scene Schema` 或 JSON 场景描述
- 抽象常见任务模板：新场景、按钮、角色、资源加载
- 建立 `Prompt`、`Skills`、`Rules` 文档
- 规范 API 命名与目录组织
- 明确 AI 生成代码时必须遵守的边界
- 形成首版 `.windsurfrules`

### 交付物

- 场景描述草案
- AI 提示词与技能文档
- 仓库级规则文件
- 一个 AI 可生成的演示需求样例

### 验收标准

- AI 可以根据文档生成基础场景代码骨架
- 项目已有稳定提示词与规则边界
- 文档与目录能支撑持续迭代

## 风险与应对

### 风险 1：过早扩展太多功能

应对：

- 每周只解决一个架构层的核心问题
- 不同时推进 Scene、Physics、Editor 的完整实现

### 风险 2：接口命名不统一

应对：

- 从现在开始统一命名规范
- 每新增一个模块都先写简短接口说明

### 风险 3：AI 生成代码质量不稳定

应对：

- 先定义模板和约束，再放开生成
- 强制要求基于现有文档与目录结构落地

### 风险 4：Web 与 Native 行为不一致

应对：

- 关键能力优先做双端兼容验证
- 资源路径、输入行为、主循环策略优先统一

## 建议的每周输出节奏

- 周一：确认本周架构目标
- 周二到周四：实现与调整
- 周五：补文档与沉淀规则
- 周末：做示例和回顾

## 一个月后的理想状态

一个月后，项目理想上应达到以下状态：

- README 已能说明项目目标、构建方式和发展方向
- `doc/` 已形成持续维护的文档中心
- Scene-first 架构初步建立
- 基础 2D 抽象开始向 PhaserJS 靠拢
- 项目具备 AI 可理解的规则、提示词与技能模板
- 后续可以进入第二阶段：示例工程、编辑器、场景 DSL、自动化生成
