## 5. 风险点

### 风险 1：Web 端调试消耗时间超预期
**应对**：
- 优先保证最小场景能展示，不追求 UI 完整美观
- 先做最小文本和点击交互闭环
- 不在本周处理所有平台细节

### 风险 2：AI API 接入花费时间超预期
**应对**：
- 优先做本地脚本或本地代理层
- 不把前端直连第三方 API 作为第一方案
- 必要时先做"离线调用 -> 保存结果 -> 导入演示"的半自动流程

### 风险 3：Scene 系统改动导致 Web 构建失败
**应对**：
- 优先复用现有 UIComponent，不做大规模 Scene-first 重构
- 如果必须改 Scene，先在 Native 验证，再同步 Web

### 风险 4：API Key 安全问题
**应对**：
- 不在前端暴露密钥
- 不提交密钥到仓库
- 本地环境变量管理

### 风险 5：SWE1.6 输出不稳定
**应对**：
- 严格限制 Prompt 输出范围
- 明确输入输出格式
- 优先要求输出 JSON 或结构化骨架
